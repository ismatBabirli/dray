`wain` is Wain's command line. It lets you, and the agents running inside Wain, do from a terminal what you would otherwise do in the app: start sessions, list them, message them, make and message bots, save drafts, tag issues, drive a session's browser, share a dev server, and set up a server. Its main use is letting one agent fan work out into several sessions, each with its own worktree and its own row in the sidebar.

Every command talks to Wain on the same machine. On a Mac that is the background server the app runs, which keeps running after you quit the app. On a Linux server with no app, it is the Wain server. See [Connect a server](/server). To act on another machine, see [Other machines](#other-machines).

## Install

The Wain app installs `wain` for you, on a Mac and in the Linux app. Each time it starts, it puts the copy it ships in `~/.local/bin`, along with the skill. Agents in Wain find it there. To run it from your own terminal, add `~/.local/bin` to your `PATH` if it is not on it already.

Anywhere else, install it with:

```bash
curl -fsSL https://www.wainhq.com/install.sh | sh
```

On Windows, in PowerShell:

```powershell
irm https://www.wainhq.com/install.ps1 | iex
```

This puts `wain` (and `wain-serve`, the server) in `~/.local/bin`. Set `WAIN_INSTALL_DIR` to put them somewhere else. If that directory is not on your `PATH`, the installer says so and prints the line to add.

It also installs the skill that teaches your agents to use `wain`. See [The skill](#the-skill).

On a machine without the app, a first install goes on to `wain server install`, which makes the machine a Wain server. See [Servers](/cli/servers).

Check what you have:

```bash
wain --version
```

## Update

```bash
wain update
```

This finds the newest release and stops if you already have it, so it is safe to run often. Otherwise it installs the new binary over the one you ran, in the same directory, and rewrites the skill.

| Flag | What it does |
|---|---|
| `--channel stable` or `--channel beta` | Which releases to take. Beta takes stable releases too. Defaults to the channel this binary came from, so a beta install stays on beta. |
| `--force` | Install the newest release even if it is the one you have. Repairs a damaged binary. |

Leaving beta does not downgrade you: a beta build stays until a stable release is newer than it. To install one exact release, set `WAIN_VERSION` to its tag, like `WAIN_VERSION=cli-v0.12.1 wain update --force`.

Where the Wain app installed it, `wain update` does nothing and says so. The CLI comes with the app, so updating the app updates it.

If a background server is installed on this machine, `wain update` does not restart it, since that stops every running agent. It prints the command that does.

## How it reaches the app

Every command connects to a socket in `~/.wain`: `~/.wain/wain.sock`. Nothing on the network can reach it. Set `WAIN_ENDPOINT` to a socket path to talk to a different one.

Sessions Wain starts get two things in their environment: `WAIN_SESSION_ID`, naming the session, and `WAIN_ENDPOINT`, naming the app that started it. That is how `wain` knows which session is calling. From inside a session, a new session is nested under the caller, and `wain browser` drives the caller's own browser. From your own terminal there is no calling session, so commands that need one take `--session <id>`.

## The skill

```bash
wain skill install
```

Writes the skill to:

- `~/.claude/skills/wain/SKILL.md`, for Claude Code
- `~/.codex/skills/wain/SKILL.md`, for Codex
- `~/.agents/skills/wain/SKILL.md`, for pi

The skill is built into the binary, so it always describes the `wain` you have. The installer and `wain update` both run `wain skill install`, so you only need it by hand if a skill file was deleted.

## Shell completion

```bash
wain completion zsh > ~/.zfunc/_wain
```

Prints a completion script for `bash`, `zsh`, `fish`, `elvish` or `powershell`.

## Commands

| Command | What it does | Page |
|---|---|---|
| `wain session` | Start, list, message, rename, stop, settle and set aside sessions, switch their model, hand them to bots, and post merge and issue cards | [Sessions](/cli/sessions) |
| `wain bot` | Make, list, message, rename and delete bots, and manage their routines | [Bots](/cli/bots) |
| `wain draft` | Save a task for later, list drafts, start or remove one | [Drafts](/cli/drafts) |
| `wain issue` | Tag a session with the issues its work is against | [Issues](/cli/issues) |
| `wain browser` | Drive a session's browser: open, read, click, type, screenshot, record | [Browser](/cli/browser) |
| `wain video add` | Put a video in a session's chat, converting it to MP4 if needed | [Browser](/cli/browser#record-a-video) |
| `wain image add` | Put a PNG or JPEG screenshot in a session's chat | [Browser](/cli/browser#record-a-video) |
| `wain share` | Publish a session's dev server as a public link | [Share](/cli/share) |
| `wain server` | Make this machine a Wain server | [Servers](/cli/servers) |
| `wain login`, `wain logout` | Link this machine's Wain server to an org at wainhq.com, or unlink it | [Servers](/cli/servers#link-to-an-org) |
| `wain machine` | The list of machines this one reaches | [Servers](/cli/servers) |
| `wain update` | Install the newest release | above |
| `wain skill install` | Write the skill for your agents | above |
| `wain completion` | Print a shell completion script | above |

For how the session commands fit together, see [Orchestration](/cli/orchestration).

A command group run on its own, like `wain session`, prints its help. Every command takes `--help`.

Older spellings still work, so scripts and agents with an older skill keep running: `wain new`, `wain ls` and `wain send` are `wain session new`, `ls` and `send`; `wain setup` is `wain server install`; `wain serve` is `wain server run`; `wain share <port>` is `wain share start <port>`.

## Other machines

```bash
wain --machine vps session ls
wain --machine vps session new "Run the load test"
wain session ls --machine all
```

`--machine <name>` runs a command on another machine from `wain machine ls`, through this machine's Wain server, with the app open or not. It takes `session`, `bot`, `draft`, `issue`, `browser` and `share` commands. `wain session ls --machine all` lists this machine's sessions and every connected machine's.

A command that names a session id needs no `--machine`: an id this machine does not hold is looked for on every machine it reaches. You reach a machine this one added; it reaches you only if it added this one too. See [Servers](/cli/servers) for adding machines.

## Output and exit codes

Commands that make something print its id alone on standard output, and a sentence for you on standard error. So `id=$(wain session new "…")` captures the id.

A failure prints `wain: <reason>` and exits with 1. A command typed wrong exits with 2 and prints usage.

## When the app and the CLI disagree

The app and the CLI ship separately, so they can drift apart. When the two speak different versions, the app refuses the command and the message names which side is behind:

- "this wain CLI speaks protocol vN, the app speaks vM — run \`wain update\`" means the CLI is behind. Run `wain update` and try again.
- "… — update the Wain app" means the app is behind. Update the app.

Nothing was created or sent, so retrying after the fix is safe. Updating the app first is the smoother order: the app's next launch updates the CLI too.

## When it cannot reach the app

Three messages, and only the second means the app is closed:

- **`permission denied reaching Wain at …`** — the app may well be running. A sandbox, or the permissions on the socket's path, blocked the connection. If the command ran inside a sandbox, run it again with that sandbox lifted for this one command.
- **`Wain isn't running. Start the app and try again.`** — the app is closed. Open it.
- **`could not connect to Wain at …`** — something else went wrong, and the line says what. It says nothing about whether the app is up.

## Limits

- `wain` needs the app, or a Wain server, running on the same machine. It reaches another machine only through that, with `--machine`.
- You cannot read another session's transcript from the CLI. See [Orchestration](/cli/orchestration#limits).
- `wain` never writes to your issue tracker. See [Issues](/cli/issues).
